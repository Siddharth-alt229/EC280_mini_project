# ESP32 Auto-Routing Buck/Boost Converter Controller

Firmware for an ESP32 that regulates the output of a DC-DC converter by automatically choosing between **buck** and **boost** operation based on the live input voltage, then driving a single PWM-controlled power stage with a feedforward duty cycle (plus optional PI trim). Setpoint changes are slewed so the output ramps rather than jumps.

Built on the Arduino framework using the ESP-IDF peripheral drivers directly: continuous-mode ADC, MCPWM, LEDC, and the one-shot DAC.

---

## Features

- **Dual-channel continuous ADC sampling** of the input and output rails (ADC1, 12-bit, 80 kHz).
- **Automatic buck/boost mode selection** (`input > target` selects buck, otherwise boost), with a minimum dwell time to prevent mode chatter near the crossover.
- **Complementary buck/boost enable signals** from MCPWM with hardware dead-time.
- **Feedforward duty-cycle calculation** from the ideal buck/boost transfer functions, with optional PI correction and anti-windup.
- **Setpoint slew limiting**: the working target moves toward the requested voltage in bounded steps.
- **Analog monitor output** of the control signal on the ESP32 DAC.

## How it works

```
 Vin probe ──┐                                   ┌── buck enable  (GPIO14, MCPWM0A)
             ├─► ADC (continuous) ─► route() ────┤
 Vout probe ─┘            │                       └── boost enable (GPIO27, MCPWM0B, complementary)
                          │
                          └────► converter_out_regulator() ─► PWM gate drive (GPIO13, LEDC, 100 kHz)
                                          │
                                          └─► DAC (GPIO25): control signal monitor

 target_voltage ─► slew limiter (main loop) ─► out_desired ─► route() / regulator
```

Each pass through `loop()`:

1. **Slew limiter**: compares `out_desired` (the working setpoint) against the requested `target_voltage` and moves it by one step toward the target. Step size is clamped to `[MINIMUM_STEP_MAGNITUDE, MAXIMUM_STEP_MAGNITUDE]`. If no step has been requested, it defaults to the minimum step. Once within 0.05 V of the target, it snaps to the target.
2. **`read_adc()`**: drains the ADC buffer and updates the latest input and output voltages.
3. **`route()`**: selects buck or boost and updates the MCPWM enable outputs.
4. **`converter_out_regulator()`**: computes the duty cycle and writes it to the LEDC PWM channel.
5. The resulting control signal (0 to 1) is mirrored to the DAC as an 8-bit analog level.

### Mode selection (`routing.h`)

- `Vin > out_desired` selects **buck**; otherwise **boost**. Boost is always the complement of buck.
- A mode change is only allowed once the time since the last change exceeds `ANTI_HYSTERISIS_DELAY`. Elapsed time is measured with the CPU cycle counter and converted using a constant of `0.004166` per cycle, which assumes a **240 MHz CPU clock**, giving microseconds.
- Buck and boost outputs are generated by MCPWM timer 0 in `MCPWM_ACTIVE_HIGH_COMPLIMENT_MODE` with `DEADTIME_TICKS = 1` (500 ns at the 2 MHz timer resolution). Duty on operator A is set to 0 % or 100 % on a mode change, so these pins act as complementary mode-enable signals.

### Duty-cycle control (`converter_output_regulator.h`)

Feedforward duty from the ideal transfer functions:

| Mode  | Duty cycle              |
|-------|-------------------------|
| Buck  | `D = Vout* / Vin`       |
| Boost | `D = 1 - Vin / Vout*`   |

The final command is `clamp(D + Kp·e + Ki·∫e, 0, 1)`, where `e = Vout* - Vout`.

- **Integral term**: accumulates only while the mode is unchanged and `|e| < 2 V`; it resets otherwise and is clamped to `±ANTI_WINDUP_CLAMP`.
- **Update deadband**: the PWM duty is only rewritten when the new command differs from the previous one by 0.01 or more.
- **Hold condition**: when the output is at least 12 V and within about 0.6 V of the setpoint, regulation updates are paused.
- **Resolution**: 9-bit LEDC duty (0 to 511) at `MOS_SWITCHING_FREQ`.

### ADC scaling (`adc_setup.h`)

Raw 12-bit counts are converted with `V = 0.0061 × counts`, which gives roughly 25 V full scale. This assumes a resistor divider in front of each ADC pin.

## Hardware

Target: **classic ESP32** (the pin map relies on ESP32 ADC1 channels and the on-chip DAC).

| Function                     | GPIO | Peripheral          |
|------------------------------|------|---------------------|
| Input voltage probe          | 36 (VP) | ADC1 channel 0   |
| Output voltage probe         | 37   | ADC1 channel 1      |
| Buck enable                  | 14   | MCPWM0A             |
| Boost enable                 | 27   | MCPWM0B             |
| Converter PWM (gate drive)   | 13   | LEDC, high-speed ch 0 |
| Control-signal monitor       | 25   | DAC channel 0       |

**Notes**

- Both probe inputs must be divided down to stay within the ADC range at 12 dB attenuation.
- GPIO14 can toggle briefly during boot. Add pull-downs on gate-driver enable lines so the power stage stays off until the firmware is running.
- Verify dead-time and gate-drive behavior on a scope before connecting a real load.

## Configuration

All tunables are `#define`s at the top of `main.cpp`.

| Macro                          | Default   | Description |
|--------------------------------|-----------|-------------|
| `INPUT_PROBE_CHANNEL_ADC1`     | `0`       | ADC1 channel for Vin |
| `OUTPUT_PROBE_CHANNEL_ADC1`    | `1`       | ADC1 channel for Vout |
| `ADC_TIMEOUT_MS`               | `5`       | Timeout for each ADC read |
| `BUF_SIZE`                     | `128`     | ADC read buffer size (bytes) |
| `BUCK_ENABLE_PIN`              | `14`      | Buck enable GPIO |
| `BOOST_ENABLE_PIN`             | `27`      | Boost enable GPIO |
| `CONVERTER_CONTROL_PIN`        | `13`      | PWM gate-drive GPIO |
| `MOS_SWITCHING_FREQ`           | `100000`  | Converter PWM frequency (Hz) |
| `ENABLE_TIMER_RES`             | `2000000` | MCPWM timer resolution (Hz) |
| `ENABLE_SWITCHING_FREQ`        | `100000`  | MCPWM enable-signal frequency (Hz) |
| `ANTI_HYSTERISIS_DELAY`        | `20`      | Minimum time between mode changes (µs at 240 MHz) |
| `ANTI_WINDUP_CLAMP`            | `2`       | Integral term limit |
| `MINIMUM_STEP_MAGNITUDE`       | `0.1f`    | Smallest setpoint step per loop (V) |
| `MAXIMUM_STEP_MAGNITUDE`       | `1.0f`    | Largest setpoint step per loop (V) |
| `PROPORTIONAL_FEEDBACK_FACTOR` | `0.0f`    | Kp (0 means feedforward only) |
| `INTEGRAL_FEEDBACK_FACTOR`     | `0.0f`    | Ki (0 means feedforward only) |

`DEADTIME_TICKS` lives in `routing.h`.

> With both feedback gains at `0.0f`, the converter runs open-loop on the feedforward duty. Increase `PROPORTIONAL_FEEDBACK_FACTOR` and `INTEGRAL_FEEDBACK_FACTOR` to close the loop.

## Usage

Set the desired output voltage by writing `target_voltage`, then raise the ready flag. Request a step size the same way:

```cpp
target_voltage = 12.0f;
target_ready_flag.store(1, std::memory_order_release);

requested_step = 0.5f;   // optional, volts per loop iteration
step_ready_flag.store(1, std::memory_order_release);
```

These variables are shared across contexts through `std::atomic` flags, so they can be set from another FreeRTOS task, a serial command handler, or a callback. The firmware does not set them itself, so **until something writes `target_voltage` the target stays at 0 V**.

## Project structure

```
src/
├── main.cpp                      # Setup, setpoint slew limiter, main control loop
├── adc_setup.h                   # Continuous ADC init and sample decoding
├── routing.h                     # Buck/boost mode selection and MCPWM enable outputs
└── converter_output_regulator.h  # Feedforward + PI duty-cycle controller, LEDC PWM
```

`converter_output_regulator.h` includes `<adc_setup.h>` with angle brackets, so the headers need to be on the include path (for example in PlatformIO's `include/` or `lib/` directory).
